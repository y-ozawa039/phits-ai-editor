# PHITS AI Editor: MVP仕様・実装計画

- 文書状態: Draft 0.8（Windows α実装基準）
- 作成日: 2026-09-04
- 更新日: 2026-09-05
- 対象: Windows 11 x64 / ChatGPT Desktop Linux版が公式対応するUbuntu LTS x86_64
- 仮称: PHITS AI Editor（正式名称は未決定）

### 実装状態（2026-09-05）

- Windows 11 x64向けα版のソース、テスト、NSISビルドを実装済み。
- 編集、言語支援、通常実行、本番実行、ANGEL、DCHAIN、PHIG-3D、Codex App Server連携を実装済み。
- Rust単体テスト、Clippy、rustfmt、TypeScriptテスト、型検査、Viteビルドを自動検証する。
- Windows実機の一連のGUI操作受入、5回比較ベンチマーク、Ubuntu 24.04/26.04実機またはVM検証は配布前受入として未実施。
- 開発用bundle identifierは`local.phits-ai-editor`、Codex CLIの検証基準は0.153.1。

## 1. 目的

現行のPHITS-Padが提供するシンプルなPHITS入力編集・編集支援・関連プログラム起動機能を踏襲し、画面右側にCodex App Serverを利用するAI支援パネルを追加したクロスプラットフォーム向けデスクトップアプリケーションを構築する。

基本的な製品像は次のとおりとする。

> 現行PhitsPad相当のエディター + 右側のCodexパネル

PHITSエディター機能はCodex未導入・未ログイン・オフライン時にも単独で利用できることを必須とする。

## 2. 設計原則

1. PHITS本体、言語資産、公式実行ラッパーを再利用し、PHITS固有ロジックを重複実装しない。
2. PHITSの実行とCodexの実行を分離する。
3. MVPでは、Codexが自律的にPHITSを起動しない。
4. 長時間のPHITS計算はエディターから切り離して継続できる。
5. PHITS入力と出力をユーザーの任意の計算ディレクトリに保持する。
6. 会話本文の正本はCodexに任せ、エディターはプロジェクトとの関連情報のみ保持する。
7. OS固有処理をRust側のアダプターに隔離し、UIと言語支援を共通化する。
8. フロントエンドから任意のシェルコマンドを直接実行できない構造にする。

## 3. 技術構成

### 3.1 採用候補（確定方針）

| 領域 | 技術 |
|---|---|
| デスクトップ基盤 | Tauri 2 |
| バックエンド | Rust |
| フロントエンド | React + TypeScript + Vite |
| エディター | Monaco Editor |
| PHITS言語データ | `phits-language-source.json`から生成された`phits-spec.json` |
| Codex連携 | Codex App Server、ローカル`stdio`、JSONL/JSON-RPC |
| プロジェクト状態 | プロジェクト内JSON（MVP） |
| グローバル設定 | TauriのOS別アプリデータディレクトリ |

### 3.2 構成図

```text
Tauri Application
├─ React / TypeScript
│  ├─ Monaco Editor
│  ├─ PHITS language service
│  ├─ Codex panel
│  ├─ Program menu
│  └─ Run/output panel
│
└─ Rust Core
   ├─ WorkspaceService
   ├─ FileEncodingService

```

### 3.3 sidecar方針

MVPでは専用sidecarを同梱しない。

- PHITSはユーザー環境の`PHITSPATH`から公式ラッパーを利用する。
- Codexはユーザー環境にインストールされた`codex`コマンドを利用する。
- 言語支援は`phits-spec.json`をTypeScriptから直接利用する。
- Node.js製LSPサーバーは将来必要になった段階で採用を再検討する。

## 4. 対応環境

### 4.1 MVP対象

- Windows 11 x64
- Ubuntu 24.04 LTS x86_64
- Ubuntu 26.04 LTS x86_64
- PHITSがローカルにインストール済みであること
- AI機能を使う場合はCodex CLIがインストール・認証済みであること

Ubuntuについては、ChatGPT Desktop Linux版が公式にサポートするLTS版だけを対象とする。上記2版は2026-09-04時点の公式対応状況に基づく。開発・配布時にはOpenAI公式ドキュメントを再確認し、対応LTS版が変更されていればサポートマトリクス、CI、配布物および試験対象を更新する。ChatGPT Desktop Linux版がプレビュー提供中である点も、リリースノートと利用上の注意に明記する。

### 4.2 MVP対象外

- Windows 10の動作保証
- ARM64
- macOS
- リモートPHITS実行
- クラスター・ジョブスケジューラー連携
- PHITS本体またはCodex CLIのアプリへの同梱

### 4.3 PHITSバージョン互換性

検証基準バージョンをPHITS 3.37とする。バージョンによる動作方針は次のとおりとする。

| 検出バージョン | 区分 | 動作 |
|---|---|---|
| 3.37 | 検証済み・正式対応 | 警告なしで利用可能 |
| 3.37より新しいバージョン | 未検証互換 | 未検証であることを警告した上で利用可能。実行を禁止しない |
| 3.37より古いバージョン | 非対応 | 入力編集は許可するが、PHITS実行は無効化して理由を表示 |
| バージョンを検出できない | 不明 | 検出不能を警告した上で利用可能。実行を禁止しない |

- 「正式対応」は実機で編集、通常実行、本番実行、停止、状態復元を検証したバージョンを意味する。
- 新しいPHITSを一律に拒否せず、公式ラッパーと必要ファイルが利用可能ならbest-effortで動作させる。
- 未検証警告には、検出バージョン、検証基準3.37、継続または中止を表示する。同じPHITSインストール先・同じバージョンについてはユーザーが警告確認を記憶できる。
- 診断画面にPHITSインストール先、検出バージョン、互換区分、ラッパー検出結果を表示する。
- バージョン比較は数値要素として行い、文字列の辞書順比較を使用しない。

## 5. ワークスペース仕様

### 5.1 ワークスペースの単位

開いている`.inp`または`.pht`ファイルの親ディレクトリをPHITSワークスペースとする。

MVPでは、1ワークスペースにつきPHITS主入力ファイルを1ファイルだけ許容する。主入力候補はワークスペース直下にある`.inp`または`.pht`ファイルとし、大文字・小文字を区別せず数える。サブディレクトリ内のファイルは主入力候補として数えない。

- 主入力候補が0件の場合、新規入力ファイルを1件作成できる。
- 主入力候補が1件の場合、そのファイルをワークスペースの主入力として扱う。
- 主入力候補が2件以上の場合、MVPではワークスペースを開かず、複数入力が未対応であることを表示する。ファイルの削除、移動、改名は自動実行しない。
- 主入力が存在するワークスペース内では、2件目の`.inp`または`.pht`を新規作成・名前を付けて保存できない。別ディレクトリへの保存は許可する。
- 将来の複数入力対応に備え、`workspace.json`には主入力の相対パスを明示的に保存する。
- `.inc`、材料・形状定義、データファイル等の補助テキストは複数存在してよく、EditorとCodexから編集できる。
- 補助ファイルはPHITS実行ボタンの直接の対象にしない。`.inp`または`.pht`拡張子を付けた補助ファイルは主入力候補として数えられるため、MVPでは別拡張子またはサブディレクトリを使用する。

例:

```text
D:\experiment\Angio_room\2026\20260326_water_phantom_and_table\
├─ water_phantom.inp
├─ geometry.inc
├─ material.inc
├─ phits.out
└─ .phits-editor\
```

Codexスレッドの`cwd`にも、この親ディレクトリを指定する。`.phits-editor`自体を`cwd`にはしない。

### 5.2 プロジェクト内メタデータ

```text
.phits-editor\
├─ workspace.json
├─ backups\
├─ codex\
│  ├─ threads.json
│  ├─ context.md
│  └─ exports\
├─ runs\
└─ .gitignore
```

#### `workspace.json`

- スキーマバージョン
- ワークスペースUUID
- 主入力ファイルの相対パス
- ワークスペース固有設定
- 絶対パスは原則として保存しない

#### `codex/threads.json`

- ワークスペースの主入力とCodexスレッドIDの関連
- 会話タイトル
- 最終利用日時
- 1つの主入力に対する複数のCodexスレッドの関連付け

会話本文そのものは保存しない。スレッドIDが別端末・別Codex環境で利用できない場合は、利用不能として扱い、新規スレッドを作成できるようにする。

#### `codex/context.md`

- 計算目的
- プロジェクト固有条件
- Codexへ継続的に伝えたい事項
- 新規Codexスレッド開始時にコンテキストとして利用する

#### `codex/exports/`

- ユーザーが明示的にエクスポートした会話記録
- MarkdownまたはJSON形式
- 自動的な会話全文の複製は行わない

#### `runs/`

- 通常実行または本番実行を開始する直前の最小メタデータ
- 入力ファイルの相対パス、開始要求時刻、実行モード、入力ハッシュ、検出したPHITSバージョンなど
- 各実行について`<run-id>/run.json`と、元の拡張子を維持した入力スナップショットを保存する
- MVPのスナップショット対象は主入力だけとし、補助ファイル一式の保存はMVP後とする
- 本番計算中にEditor由来のプロセスが状態を書き換えることはない
- PHITSの正式な計算出力は従来どおり入力ディレクトリに生成する

#### `backups/`

- ファイル保存時の直前版バックアップ
- ファイルごとに1世代だけ保持する
- バックアップは元ファイルの隣へ作らず、`.phits-editor/backups/`内へ保存する

### 5.3 作成タイミング

`.phits-editor`は入力ファイルを開いただけでは作成しない。次のいずれかで初めて作成する。

- Codexパネルから最初のメッセージを送る
- 「AIワークスペースを初期化」を選択する
- プロジェクト固有設定を保存する
- 通常実行または本番実行を開始する
- 初回の直前版バックアップを作成する

### 5.4 書き込み不能時

計算ディレクトリが読み取り専用の場合は、メタデータをTauriのアプリデータディレクトリへ退避し、UIに保存場所を表示する。

### 5.5 アプリ全体設定

次の端末固有情報はワークスペースではなく、OSが定めるTauriのアプリ設定ディレクトリへ保存する。

- 手動指定した既定PHITSインストール先
- PHITS未検証バージョン警告の確認状態
- ウィンドウ配置、フォント等のUI設定
- 最近開いたワークスペース

CodexのAPIキー、アクセストークン、セッション情報は保存しない。

%PHITSPATH%\workbench\language_support\data\phits-spec.json

## 8. ファイル処理

### 8.1 文字コード

- UTF-8およびWindows-31J/Shift_JISを扱う。
- 読み込んだファイルの文字コードを可能な限り維持する。
- BOMおよび改行コードを維持する。
- 保存時に暗黙の文字コード変換を行わない。
- ステータスバーへ現在の文字コードと改行形式を表示する。
- 新規ファイルの既定文字コードはUTF-8（BOMなし）、改行はOS既定とする。
- PHITS 3.37で日本語コメントを含むUTF-8入力の編集・実行互換性を受入試験し、不適合の場合はリリース前に既定値を再検討する。

### 8.2 未保存ファイルの実行

実行前に未保存変更がある場合は、次を提示する。

- 保存して実行
- キャンセル

MVPでは未保存内容を一時ファイルとして実行しない。

### 8.3 保存とバックアップ

- 通常の保存は、一時ファイルへの書き込みと同期に成功してから置換する原子的保存とする。
- 上書き保存の直前内容を`.phits-editor/backups/`へ退避し、ファイルごとに1世代だけ保持する。
- 編集中の内容を元ファイルへ自動保存しない。
- バックアップからの復元はユーザー操作で行い、Editorが自動的に元ファイルを上書きしない。

### 8.4 巨大ファイル

- 巨大なPHITS出力をMonacoへ無制限に読み込まない。
- 出力パネルでは末尾または制限された行数だけを保持する。
- 完全な出力は外部ファイルとして開けるようにする。
- 入力行数2,000行を超える場合は、編集支援処理を調整できる設計にする。現行PhitsPadの設定値を初期参考値とする。

## 9. プログラム実行

### 9.1 共通原則

- 内部実行ファイルを直接呼ばず、PHITS配布物の公式ラッパーまたは公式起動経路を利用する。
- 入力ファイルの親ディレクトリを作業ディレクトリとする。
- ラッパーへはフルパスではなく入力ファイル名を渡す。
- 同じ作業ディレクトリで複数のPHITSジョブを同時実行しない。
- Rust側で入力パスを検証し、フロントエンドから任意コマンドを渡さない。
- 通常実行・本番実行のいずれも、PHITS起動直前に主入力のスナップショットと最小実行メタデータを`.phits-editor/runs/<run-id>/`へ保存する。この処理は起動前に完了し、計算中の監視処理を伴わない。
- 実行前に既存の`phits.out`、`batch.out`および既知のタリー出力を検出し、上書きされる可能性を確認画面に表示する。
- 既存出力を自動削除、移動、改名しない。ユーザーは続行またはキャンセルを選ぶ。

PHITSインストール先の選択優先順位:

1. ユーザーが明示的に設定したワークスペース固有のPHITSパス
2. 環境変数`PHITSPATH`
3. アプリ全体で手動設定したPHITSパス
4. 未検出として診断画面を表示

既定では`PHITSPATH`を利用し、ワークスペース固有設定は複数のPHITSインストールを明示的に使い分ける場合だけ作成する。選択したインストール先と検出バージョンを実行確認画面に表示する。

### 9.2 PHITSラッパー

Windows:

```text
%PHITSPATH%\workbench\task\win\run_phits_no_pause.ps1
```

Linux:

```text
$PHITSPATH/workbench/task/linux/run_phits_no_pause.sh
```

### 9.3 関連プログラム

- ANGEL
- DCHAIN
- PHIG-3D

各OSの`workbench/task/<platform>/`にある実行手順・ラッパーを利用する。関連プログラムごとにRustの限定アダプターを用意する。

## 10. PHITS実行モード

### 10.1 確定仕様

MVPではPHITS実行はユーザー操作からのみ開始する。「通常実行」と「本番実行（計算優先）」の2モードを提供する。

CodexによるPHITS実行要求はMVP後に追加し、ユーザー承認後に同じRust Runnerを使用する。

### 10.2 モード比較

| モード | PHITSプロセス | Codex | UI | エディター終了 |
|---|---|---|---|---|
| 通常実行 | エディターが管理 | 利用可能 | 編集・会話・リアルタイム出力 | 実行中は確認が必要 |
| 本番実行（計算優先） | エディターから完全に切り離す | PHITS起動前にApp Serverを終了 | 終了準備後、PHITSをspawnして直ちに終了 | 計算継続 |

### 10.3 通常実行

- 短時間の試験、入力デバッグ、実行結果の即時確認に使用する。
- stdout/stderrを出力パネルへ表示する。
- 実行中の通常実行を本番実行へ切り替える機能はMVPでは提供しない。本番実行はPHITS起動前に選択する。
- 実行中にエディターを閉じる場合は次を提示する。
  - 停止
  - 閉じるのを中止

### 10.4 本番実行（計算優先）

長時間または計算資源を優先したいPHITS計算に使用する。本番実行の開始フローは次のとおりとする。

1. 未保存ファイルがあれば保存確認を表示する。
2. 実行対象と作業ディレクトリを確認し、起動に必要な引数をすべて確定する。
3. 入力ファイルの相対パス、開始要求時刻、実行モード、入力ハッシュ、検出したPHITSバージョン等の最小メタデータを`.phits-editor/runs/`へ保存する。
4. Codex App Serverを終了する。
5. Monacoの言語支援、ファイル監視、タイマー等、Editor内の非必須バックグラウンド処理を停止する。
6. PHITSをEditorから完全に切り離した独立プロセスとしてspawnする。
7. OS APIがプロセス生成に成功したことだけを確認し、Editorを直ちに終了する。
8. 以後はPHITSだけで計算を継続する。

追加仕様:

- 「起動成功」はOSレベルのプロセス生成成功だけを意味する。PHITS内部の初期化、入力解析、geometry errorの有無までは待たない。
- PHITSとCodex App Serverが同時に稼働する期間を設けない。
- PHITSとEditorが共存するのは、spawn成功からEditor終了までの最短期間だけとする。その間にポーリング、ログ解析、追加メタデータ書き込みを行わない。
- 本番計算中は、Supervisor、常駐Launcher、監視画面、ポーリング処理などEditor由来のプロセスを一切残さない。
- 本番実行ではEditor独自のstdout/stderr監視・収集を行わず、PHITSおよび公式ラッパーが生成する既存ファイルを正本とする。OS上のハンドル切り離しに出力先指定が必要な場合も、常駐プロセスを介さず起動時に直接設定する。
- spawnに失敗した場合はEditorを終了せずエラーを表示する。Codex App Serverは必要になった時点で再起動できるようにする。
- 常駐監視画面は設けない。進捗はPHITS出力ファイルを直接確認するか、Editorを再起動して確認する。
- Editor再起動時に限り、`phits.out`、`batch.out`、タリー出力等のPHITS生成ファイルを一度読み、実行中候補、完了、異常・中断候補、不明の状態を判定する。
- 状態判定に利用するファイル名、終了文字列、更新条件は、対象PHITS版の実出力を調査してPhase 4で確定する。断定できない場合は`不明`と表示し、推測で完了扱いしない。
- 再起動して状態を確認した後も、PHITSプロセスへ従属関係を設定しない。
- 計算終了時にエディターやCodex App Serverを自動起動しない。
- OSのプロセス優先度やCPU affinityはMVPでは変更しない。まずエディターとCodexを終了することで計算資源を解放する。

### 10.5 停止

- 通常停止では、可能な場合に`batch.out`の先頭値を`0`へ変更し、現在バッチ終了後の停止を要求する。
- 本番実行中はEditor由来の停止待受プロセスを置かない。停止する場合はEditorを再起動して対象実行を選ぶか、ユーザーがPHITS標準手順で`batch.out`を操作する。
- `batch.out`停止が利用できない場合、または即時停止が明示された場合の強制停止は段階的に実装する。
- Windowsではプロセスツリー、Linuxではプロセスグループを安全に扱う必要がある。

## 11. Codex連携

### 11.1 接続

- Rustから`codex app-server`を子プロセスとして起動する。
- 既定の`stdio`トランスポートを使用する。
- JSONLとしてJSON-RPCメッセージを送受信する。
- WebSocket接続はMVPでは使用しない。
- Codex CLIが未導入、未認証、オフライン、または起動不能の場合でも、エディター機能とユーザー操作によるPHITS実行は利用可能とする。
- Codexの認証はユーザー環境にある既存のCodex CLIへ委ね、EditorはAPIキー、アクセストークン、セッション情報を保存しない。
- Codex App ServerはCodexパネルを初めて利用する時点で遅延起動する。

### 11.2 ライフサイクル

1. App Server起動
2. `initialize`
3. `initialized`
4. `thread/start`または`thread/resume`
5. `turn/start`
6. イベントを右側パネルへストリーム表示
7. 必要に応じて`turn/interrupt`
8. 本番実行開始時またはアプリ終了時にApp Serverを終了

### 11.3 会話保存

- 会話本文・ターン・ツール実行履歴はCodex App Server側を正本とする。
- エディターは`thread.id`とワークスペースの主入力との関連だけを`.phits-editor/codex/threads.json`へ保存する。
- `thread/read`、`thread/list`、`thread/resume`を通じて履歴を参照・再開する。
- Codexの内部JSONLまたは内部SQLiteを直接操作しない。

### 11.4 権限

MVPの確定初期値:

- Codexの`cwd`: 開いているPHITSワークスペース
- サンドボックス: `workspaceWrite`
- 読み取り: 開いているワークスペース内を許可。ワークスペース外は許可しない
- 書き込み可能範囲: 開いているワークスペース内だけ
- ファイル変更: 適用前に差分を表示し、ユーザーの明示的承認を求める
- コマンド実行: コマンド、引数、作業ディレクトリを表示し、実行ごとに承認を求める
- ネットワーク: 既定で無効。必要時のみ目的を表示してユーザー承認を求める
- 読み取り専用の相談モードを用意する

承認UIでは少なくとも、対象スレッド、対象ターン、操作内容、作業ディレクトリ、許可範囲を表示する。

### 11.5 コンテキスト送信

自動的に全ファイル・全出力を送らない。ユーザー要求に応じて次を文脈として利用する。

- アクティブな入力ファイル
- 選択範囲
- カーソル位置
- 診断メッセージ
- 明示的に選択されたPHITS出力
- `.phits-editor/codex/context.md`

大きな出力は必要部分だけを渡し、完全なファイルはローカルパスとしてCodexが必要時に読む。

### 11.6 CodexによるPHITS実行（MVP後）

1. CodexがPHITS実行を要求する。
2. エディターが入力ファイル、作業ディレクトリ、実行モードを示す承認画面を表示する。
3. ユーザー承認後、Codexではなくアプリ所有のRust Runnerが公式ラッパーを起動する。
4. 実行結果をCodexのツール結果として同じスレッドへ返す。

実験的APIへの依存はアダプター内へ隔離し、MVPでは採用しない。

## 12. リソース管理

### 12.1 基本方針

- 待機中のエディターCPU使用を最小化する。
- 大量出力の再描画・再解析を行わない。
- Codexを使わない間はApp Serverを遅延起動できるようにする。
- 本番実行ではPHITSを起動する前にApp ServerとEditor内の非必須処理を停止し、spawn成功直後にエディター本体を終了する。
- 本番PHITS計算はエディターの生存に依存しない。
- 本番実行の計算終了後も、エディターやApp Serverを自動起動しない。
- 本番計算中にEditor由来の常駐プロセスやポーリング処理を残さない。

### 12.2 性能受入目標（暫定）

代表的PHITS入力を使い、次を比較する。

1. 公式ラッパー単独
2. エディターを開きCodex未接続
3. エディターを開きCodex App Server待機
4. 本番実行後にエディター終了

測定項目:

- PHITS経過時間
- PHITS CPU時間
- システムメモリ
- ページング
- ディスクI/O
- OpenMP/MPIスケーリング

暫定目標は、Codex未接続・エディター待機時のPHITS性能差を実行変動込みで2%以内とする。物理メモリ不足時はエディター終了を推奨する。

## 13. セキュリティ・プライバシー

- フロントエンドへ任意コマンド実行APIを公開しない。
- Rust Runnerは既知のPHITS関連プログラムと公式ラッパーだけを起動する。
- パスをコマンド文字列へ連結せず、実行ファイルと引数を分離する。
- Codexへ送るファイル・選択範囲をUIで確認可能にする。
- 会話履歴やスレッドIDをGitへ誤登録しないよう`.gitignore`を生成する。
- `.phits-editor`全体をGit対象外にする設定も提供する。
- 認証情報をプロジェクトディレクトリへ保存しない。
- 利用状況テレメトリー、解析イベント、クラッシュ情報を自動送信しない。
- 診断情報はユーザーが明示的に生成・保存した場合だけ出力し、外部へ自動送信しない。

## 19. リスクと対策

| リスク | 対策 |
|---|---|
| App Server仕様変更 | `CodexAppServerClient`へ隔離し、Codexバージョンを検出して生成スキーマと互換試験を行う |
| PHITS実行がエディター終了に巻き込まれる | 本番実行をOS固有の切り離し起動として統合試験する |
| Codex停止後にPHITSのspawnが失敗する | Editorを終了せずエラーを表示し、Codexは必要時に再起動できるようにする |
| PHITS生成ファイルだけでは終了状態を断定できない | 状態を`不明`として扱い、対象PHITS版ごとの判定規則を実出力で検証する |
| 3.37より新しいPHITSでラッパーや出力形式が変更される | 未検証警告を表示し、バージョン依存処理をアダプターへ隔離する。利用を禁止せず、問題報告に診断情報を添付できるようにする |
| メモリ不足でPHITSが低速化 | 本番実行時にApp Serverとエディターを終了し、性能受入試験を行う |
| 巨大出力でUIが停止 | 出力保持量を制限し、全文はファイルとして扱う |
| 文字コード破損 | 元エンコーディング・BOM・改行を保持し、往復テストを行う |
| 同一フォルダで出力が衝突 | フォルダ単位の実行ロックを設ける |
| 既存ディレクトリに複数の主入力候補がある | MVPでは開く処理を中止して対象ファイルを列挙し、ユーザー自身による整理または別ディレクトリ利用を案内する |
| スレッドIDが別端末で無効 | App Serverで存在確認し、新規作成・再関連付けを可能にする |
| 任意コマンド実行の露出 | Rust側の限定RunnerとCodex承認UIを使用する |

1. 正式名称（開発中はPHITS AI Editor）と正式bundle identifier
2. リリース時点のChatGPT Desktop Linux版公式対応Ubuntu LTS

## 22. 確定事項の要約

- UIは「現行PhitsPad相当 + 右側Codexパネル」とする。
- Tauri 2 + Rust + React/TypeScript + Monacoを採用する。
- Windows 11 x64と、ChatGPT Desktop Linux版が公式対応するUbuntu LTS x86_64を対象とする。2026-09-04時点ではUbuntu 24.04 LTSおよび26.04 LTSを対象とする。
- PHITS 3.37を検証済み・正式対応版とし、それより新しい版とバージョン検出不能時は警告付きで実行を許可する。3.37より古い版では入力編集だけを許可し、PHITS実行を無効化する。
- 任意の`.inp`親ディレクトリをワークスペースとし、MVPではワークスペース直下の`.inp`または`.pht`主入力を1ファイルに限定する。
- 主入力以外の補助テキストは複数編集可能とするが、実行対象にはしない。
- プロジェクト固有メタデータを`.phits-editor`へ保存する。
- 会話本文はCodex側を正本とし、プロジェクトには関連情報のみ保存する。
- 既存ファイルの文字コード・BOM・改行を維持し、新規ファイルはUTF-8（BOMなし）を既定とする。
- 原子的保存と、`.phits-editor/backups/`内の直前版バックアップ1世代を採用し、元ファイルへ自動保存しない。
- PHITS実行は公式ラッパーを使用し、同じフォルダで同時実行しない。
- PHITSパスは明示的なワークスペース設定、`PHITSPATH`、アプリ全体設定の順で選択する。通常は`PHITSPATH`を使用する。
- 実行直前に主入力スナップショットと最小メタデータを保存し、既存出力の上書き可能性を警告する。既存出力は自動整理しない。
- MVPではPHITS実行はユーザー操作からのみ開始する。
- 「通常実行」と「本番実行（計算優先）」の2モードを実装する。
- 実行中の通常実行から本番実行への途中切替は行わず、本番実行は起動前に選択する。
- 本番実行では、PHITS起動前にApp ServerとEditor内の非必須処理を停止し、OSレベルのspawn成功だけを確認した直後にEditorを終了する。
- 本番計算中はSupervisor、常駐Launcher、監視・ポーリング処理を残さず、次回起動時にPHITS生成ファイルから状態を判定する。
- Codex未導入・未認証・オフラインでも、編集とユーザー操作によるPHITS実行を利用可能とする。
- Codexはワークスペース内だけを読み書き対象とし、ファイル変更は差分承認、コマンドは実行ごとの承認とする。
- MVPのUIは日本語とし、将来の英語化が可能なリソース構造にする。
- WindowsはNSIS、Ubuntuは`.deb`を第一配布形式とし、PHITS本体とCodex認証情報を同梱しない。
- テレメトリーや診断情報を自動送信しない。
- Codexによる承認付きPHITS実行はMVP後に追加する。
