# PHITS AI Editor 0.0.5-alpha

日本語 | [English](release-notes-v0.0.5-alpha.en.md)

`0.0.5-alpha`では、アクション承認に境界付きの自律モードを追加し、Codexからの
PHITS通常実行要求をエディタ所有の実行経路へ接続します。

## 主な変更

- 「自律実行（ワークスペース内）」を追加しました。Rust側で検証できた
  ワークスペース内のファイル変更と、現在選択中の保存済みPHITS入力の通常実行は、
  操作ごとの確認なしで進められます。
- CodexがPHITS実行を求められた場合、PHITSをshellから直接起動せず、エディタが
  一時的に提供する`run_phits`ツールを呼び出します。エディタは要求を検査し、
  既存のRust RunnerとPHITS公式ラッパーで実行して、結果を同じCodexターンへ返します。
- 「確認優先」ではPHITS実行ごとに確認し、「必要時のみ確認」では今回のみ、または
  現在のCodex接続中に限った許可を選べます。「相談のみ」では実行を拒否します。
- PHITS実行の承認表示には入力ファイル、作業ディレクトリ、PHITSルート、
  PHITSバージョン、実行理由を表示します。
- 未保存の入力、現在選択中の入力と異なる対象、ワークスペース外パス、状態不明の
  前回実行、同じフォルダーでの重複実行は、承認モードにかかわらず拒否します。
- 承認カードの冒頭に、ファイル変更、PHITS実行、対応する読取・一覧・検索コマンドの
  補足説明を表示します。その他のコマンドは、コマンド全体と要求理由の確認を促します。
  コマンド規則の候補は追加権限と分け、今回だけの許可との違いを説明します。
- MCPツール承認（`mcpServer/elicitation/request`）とツールの確認・入力要求に対応しました。
  エディタ専用`run_phits`への入口は、同じターンのツール項目・引数と照合した場合だけ
  エディタの実行審査へ転送します。入口の通過だけではPHITSは実行されません。
- ユーザーの拒否・取消、エディタの権限制限、未対応要求を区別してCodexパネルと
  出力欄に表示します。未対応の場合は要求method、requestId、threadId、turnId、理由を
  記録し、回答内容や認証情報は診断ログへ含めません。
- 最新CLIの定期CIへ、実App Serverとローカル模擬AI・MCPによる許可・拒否・取消から
  結果返却までの試験を追加しました。実際のPHITS計算や利用者のアカウントは使いません。
- [全要求の対応範囲](codex-request-coverage.md)を日本語・英語で公開し、新規の未分類要求や
  必要なパラメーターの欠落をSchema検査で検出します。実CLI試験は入力付きフォームと
  追加権限要求も含む12ケースへ拡張しました。

## Codex確認要求の対応範囲

Codexから届く確認要求を「対応済み」「意図的に制限」「利用対象外」「未対応」に分類しました。
要求名だけでなく、MCP入力フォームの対応形式・制約と、追加権限を付与しない方針も記載しています。
接続成功がすべての要求形式への対応を意味するわけではありません。

分類表：[日本語](https://github.com/y-ozawa039/phits-ai-editor/blob/v0.0.5-alpha/docs/codex-request-coverage.md) /
[English](https://github.com/y-ozawa039/phits-ai-editor/blob/v0.0.5-alpha/docs/codex-request-coverage.en.md)

分類表はソースコードとポータブル版ZIPの`docs`フォルダーにも収録します。
新しい未分類要求が追加された場合はCIで検出し、対応の要否を確認します。

## 安全境界

Codexへ無制限のshell権限は渡しません。PHITS、ANGEL、DCHAIN、PHIG-3Dの直接コマンド、
ネットワーク利用、ワークスペース外書込みは引き続き制限されます。自律モードでも
`dangerFullAccess`や無条件のコマンド承認は使用しません。計算優先実行はエディタと
Codexを終了するため、従来どおりツールバーからユーザーが明示的に開始します。

PHITS本体、Codex CLI、認証情報は同梱しません。公式配布対象はWindows 11 x64です。

MCPフォームは基本的な文字列・選択肢・真偽値・数値に対応します。URL型、拡張フォーム、
未対応の制約は自動許可せず、未対応として理由を表示します。独立した追加権限要求には
新しい権限を付与しません。接続できることは、今後のすべての要求形式への対応を保証しません。
