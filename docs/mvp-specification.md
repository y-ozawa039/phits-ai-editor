# PHITS AI Editor: MVP仕様・実装計画

- 文書状態: Draft 0.8（Windows alpha実装基準）
- 作成日: 2026-09-04
- 更新日: 2026-09-11
- `0.0.1-alpha`対象: Windows 11 x64（Ubuntu LTS x86_64は将来の移植対象）
- 仮称: PHITS AI Editor（正式名称は未決定）

### 実装状態（2026-09-05）

- Windows 11 x64向けalpha版のソース、テスト、NSISビルドを実装済み。
- 編集、言語支援、通常実行、本番実行、ANGEL、DCHAIN、PHIG-3D、Codex App Server連携を実装済み。
- Rust単体テスト、Clippy、rustfmt、TypeScriptテスト、型検査、Viteビルドを自動検証する。
- 現在のWindows 11 x64 PCでは、一連のGUI操作、PHITS・補助ツール、実App Server承認、5回比較ベンチマークのalpha版受入を完了済み。
- 別のWindows 11 x64端末で、インストール、`.inp`の「プログラムから開く」、上書き保存、アンインストール、およびCodexによる編集・差分採用・Undo・直前差分の再表示まで受入済み。PHIG-3Dは開発PCで連携確認済みだが、別端末ではPHIG-3D自体を起動できず、同端末での連携は未判定。Ubuntu実機またはVM検証は初回alphaの公開条件に含めず、将来の移植作業として扱う。
- 開発用bundle identifierは`local.phits-ai-editor`、Codex CLIの検証基準は0.153.1。

## 1. 目的

現行のPHITS-Padが提供するシンプルなPHITS入力編集・編集支援・関連プログラム起動機能を踏襲し、画面右側にCodex App Serverを利用するAI支援パネルを追加したクロスプラットフォーム向けデスクトップアプリケーションを構築する。

基本的な製品像は次のとおりとする。

> 現行PhitsPad相当のエディター + 右側のCodexパネル

PHITSエディター機能はCodex未導入・未ログイン・オフライン時にも単独で利用できることを必須とする。

## 2. 設計原則

1. PHITS本体、言語資産、公式実行ラッパーを再利用し、PHITS固有ロジックを重複実装しない。
2. PHITSの実行とCodexの実行を分離する。
3. MVPでは、Codexが自律的にPHITSを起動しない。
4. 長時間のPHITS計算はエディターから切り離して継続できる。
5. PHITS入力と出力をユーザーの任意の計算ディレクトリに保持する。
6. 会話本文の正本はCodexに任せ、エディターはプロジェクトとの関連情報のみ保持する。
7. OS固有処理をRust側のアダプターに隔離し、UIと言語支援を共通化する。
8. フロントエンドから任意のシェルコマンドを直接実行できない構造にする。

## 3. 技術構成

### 3.1 採用候補（確定方針）

| 領域 | 技術 |

| プロジェクト状態 | プロジェクト内JSON（MVP） |
| グローバル設定 | TauriのOS別アプリデータディレクトリ |

### 3.3 sidecar方針

MVPでは専用sidecarを同梱しない。

- PHITSはワークスペース設定、アプリ設定、ユーザー環境の`PHITSPATH`または標準位置から検出し、公式ラッパーを利用する。
- Codexはユーザー環境にインストールされた`codex`コマンドを利用する。
- 言語支援は`phits-spec.json`をTypeScriptから直接利用する。
- Node.js製LSPサーバーは将来必要になった段階で採用を再検討する。

## 4. 対応環境

### 4.1 `0.0.1-alpha`対象

- Windows 11 x64
- PHITSがローカルにインストール済みであること
- AI機能を使う場合はCodex CLIがインストール・認証済みであること

Ubuntu LTS x86_64は将来の移植対象であり、`0.0.1-alpha`の公式バイナリおよび公開可否判定には含めない。Ubuntu向け配布を始める際に、対象LTS版、PHITS実行、Codex連携、GUI、`.deb`の実機またはVM受入を改めて定義する。

### 4.2 MVP対象外

- Windows 10の動作保証
- ARM64
- macOS
- リモートPHITS実行
- クラスター・ジョブスケジューラー連携
- PHITS本体またはCodex CLIのアプリへの同梱

### 4.3 PHITSバージョン互換性

検証基準バージョンをPHITS 3.37とする。バージョンによる動作方針は次のとおりとする。

| 検出バージョン | 区分 | 動作 |
|---|---|---|
| 3.37 | 検証済み・正式対応 | 警告なしで利用可能 |
| 3.37より新しいバージョン | 未検証互換 | 未検証であることを警告した上で利用可能。実行を禁止しない |
| 3.37より古いバージョン | 非対応 | 入力編集は許可するが、PHITS実行は無効化して理由を表示 |
| バージョンを検出できない | 不明 | 検出不能を警告した上で利用可能。実行を禁止しない |

- 「正式対応」は実機で編集、通常実行、本番実行、停止、状態復元を検証したバージョンを意味する。
- 新しいPHITSを一律に拒否せず、公式ラッパーと必要ファイルが利用可能ならbest-effortで動作させる。
- 未検証警告には、検出バージョン、検証基準3.37、継続または中止を表示する。同じPHITSインストール先・同じバージョンについてはユーザーが警告確認を記憶できる。
- 診断画面にPHITSインストール先、検出バージョン、互換区分、ラッパー検出結果を表示する。
- バージョン比較は数値要素として行い、文字列の辞書順比較を使用しない。

## 5. ワークスペース仕様

### 5.1 ワークスペースの単位

開いている`.inp`または`.pht`ファイルの親ディレクトリをPHITSワークスペースとする。

1ワークスペース内に複数のPHITS入力ファイルを許容する。実行候補はワークスペース直下にある`.inp`または`.pht`ファイルとし、大文字・小文字を区別せず判定する。サブディレクトリ内のファイルは実行候補として数えない。

- 実行候補が0件の場合、新規入力ファイルを作成できる。
- 実行候補が1件の場合、そのファイルを既定の実行対象として扱う。
- 実行候補が2件以上の場合もワークスペースを開き、直接開いたファイルまたはEditorで現在選択した入力ファイルを実行対象とする。
- 実行対象が選択されていない場合はPHITSを起動せず、`.inp`または`.pht`の選択を求める。
- 複数の`.inp`または`.pht`を新規作成・名前を付けて保存できる。ファイルの削除、移動、改名は自動実行しない。
- 最後に選択した実行対象の相対パスはアプリ全体の前回セッション情報へ保存する。
- `.inc`、材料・形状定義、データファイル等の補助テキストは複数存在してよく、EditorとCodexから編集できる。
- 補助ファイルはPHITS実行ボタンの直接の対象にしない。

ExplorerまたはOSの「プログラムから開く」で`.inp`/`.pht`を渡した場合は、その親ディレクトリをワークスペース、渡されたファイルを実行対象として直ちに開く。二重起動は新しいウィンドウを作らず既存ウィンドウへ起動要求を転送して前面化する。引数なしの通常起動では、前回のワークスペース、保存済みファイルのタブ、アクティブタブ、実行対象を復元する。未保存バッファ本文は永続化しない。異なるワークスペースへ切り替える際に未保存変更があれば破棄確認を必須とする。`.inp`/`.pht`のドラッグ＆ドロップも同じ起動処理を使用する。

例:

```text
D:\experiment\Angio_room\2026\20260326_water_phantom_and_table\
├─ water_phantom.inp
├─ geometry.inc
├─ material.inc
├─ phits.out
└─ .phits-editor\
```

Codexスレッドの`cwd`にも、この親ディレクトリを指定する。`.phits-editor`自体を`cwd`にはしない。

### 5.2 プロジェクト内メタデータ

```text
.phits-editor\
├─ workspace.json
├─ backups\
├─ codex\
│  ├─ threads.json
│  ├─ context.md
│  └─ exports\
├─ runs\
└─ .gitignore
```

#### `workspace.json`

- スキーマバージョン
- ワークスペースUUID
- 主入力ファイルの相対パス
- ワークスペース固有設定
- 絶対パスは原則として保存しない

#### `codex/threads.json`

- ワークスペースの主入力とCodexスレッドIDの関連
- 会話タイトル
- 最終利用日時
- 1つの主入力に対する複数のCodexスレッドの関連付け

会話本文そのものは保存しない。スレッドIDが別端末・別Codex環境で利用できない場合は、利用不能として扱い、新規スレッドを作成できるようにする。

#### `codex/context.md`

- 計算目的
- プロジェクト固有条件
- Codexへ継続的に伝えたい事項
- 新規Codexスレッド開始時にコンテキストとして利用する

#### `codex/exports/`

- ユーザーが明示的にエクスポートした会話記録
- MarkdownまたはJSON形式
- 自動的な会話全文の複製は行わない

#### `runs/`

- 通常実行または本番実行を開始する直前の最小メタデータ
- 入力ファイルの相対パス、開始要求時刻、実行モード、入力ハッシュ、検出したPHITSバージョンなど
- 各実行について`<run-id>/run.json`と、元の拡張子を維持した入力スナップショットを保存する
- MVPのスナップショット対象は主入力だけとし、補助ファイル一式の保存はMVP後とする
- 本番計算中にEditor由来のプロセスが状態を書き換えることはない
- PHITSの正式な計算出力は従来どおり入力ディレクトリに生成する

#### `backups/`

- ファイル保存時の直前版バックアップ
- ファイルごとに1世代だけ保持する
- バックアップは元ファイルの隣へ作らず、`.phits-editor/backups/`内へ保存する

### 5.3 作成タイミング

`.phits-editor`は入力ファイルを開いただけでは作成しない。次のいずれかで初めて作成する。

- Codexパネルから最初のメッセージを送る
- 「AIワークスペースを初期化」を選択する
- プロジェクト固有設定を保存する
- 通常実行または本番実行を開始する
- 初回の直前版バックアップを作成する

### 5.4 書き込み不能時

計算ディレクトリが読み取り専用の場合は、メタデータをTauriのアプリデータディレクトリへ退避し、UIに保存場所を表示する。

### 5.5 アプリ全体設定

次の端末固有情報はワークスペースではなく、OSが定めるTauriのアプリ設定ディレクトリへ保存する。

- 手動指定した既定PHITSインストール先
- PHITS未検証バージョン警告の確認状態
- ウィンドウ配置、フォント等のUI設定
- 最近開いたワークスペース

CodexのAPIキー、アクセストークン、セッション情報は保存しない。

## 6. UI仕様

### 6.1 基本レイアウト

```text
┌──────────────────────────────────────────────────────────┐
│ ファイル 編集 実行 表示 設定 ヘルプ                    │
├──────────────────────────────────┬───────────────────────┤
│                                  │ Codex                 │
│                                  │                       │
│        PHITS入力エディター       │ 会話・進捗・承認      │
│                                  │ 差分・エラー          │
│                                  │                       │
├──────────────────────────────────┴───────────────────────┤
│ PHITS/ANGEL/DCHAIN/PHIG-3D 出力・実行状態                │
├──────────────────────────────────────────────────────────┤
│ 行・桁 / 文字コード / 改行 / Codex状態 / PHITS状態      │
└──────────────────────────────────────────────────────────┘
```

- Codexパネルは右側に配置し、折りたたみ・幅変更を可能にする。既定幅はウィンドウ内側の1/3、最小360px、最大1/2とし、ドラッグで変更する。物理pxではなくウィンドウ幅に対する比率をアプリ全体設定へ保存し、ウィンドウのリサイズに追従する。仕切りのダブルクリックで1/3へ戻す。
- 実行出力パネルは下部に配置し、折りたたみ可能にする。
- Codexパネルを閉じてもPHITSエディター機能はすべて利用できる。
- 表示メニューはエクスプローラー、Codexパネル、出力パネルの現在状態をチェック付き項目で示し、同じ項目から表示を切り替える。
- 設定メニューではエクスプローラー、エディター、Codexパネルの文字サイズを、それぞれ12～28pxの範囲で個別に変更できる。工場出荷時の既定値はすべて14pxとし、アプリ内の文字および文字フォントで描画する記号は12px未満にしない。設定項目名と数値欄も14pxを基準とする。PowerPointに準じ、数値の直接入力と右端の単一ドロップダウン矢印を一体表示し、代表値（12、14、16、18、20、24、28px）を十分な幅の独立した候補リストへ表示する。さらに1pxずつ変更する「A↑」「A↓」ボタンを組み合わせる。変更は即時反映し、端末内へ保存して次回起動時に復元する。「現在の設定を既定設定へ反映」により、現在の3項目をユーザー既定値として保存でき、「文字サイズを既定設定に戻す」はその値を復元する。現在値とユーザー既定値はいずれもワークスペースではなくアプリ全体の設定として保存し、`.phits-editor`には書き込まない。
- 拡大側のAは17px、縮小側のAは14px、上下矢印は12pxとし、縮小操作を視覚的に区別する。アプリケーションの背景、境界線、一般操作部はニュートラルなグレー系とし、画面全体へグレースケールフィルターは適用しない。PHITS構文強調、補完・診断、正常・警告・異常を示す状態色など意味を持つ配色は維持する。Monacoの行番号は通常時`#8A8A8A`、選択行は`#555555`とする。上部メニュー、ツールバーと検索、エクスプローラー見出し、エディタータブ名、ファイル一覧、「ワークスペースなし」「入力を一緒に仕上げましょう」は`#000000`とする。無効なツールバーボタンも文字自体は黒とし、元の透明な背景を維持しながらアイコン濃度で無効状態を示す。大小のPロゴ、ワークスペースを開く主要ボタン、Codex接続ボタン、選択中のCodex切替、Codexスパーク表示は、元の青系アクセントを用いる。

### 6.2 PhitsPadから踏襲する主要機能

- 新規作成、開く、再読み込み、閉じる
- 保存、名前を付けて保存
- 元に戻す、やり直す
- 切り取り、コピー、貼り付け、すべて選択
- 検索、次を検索、前を検索、置換
- 行番号表示
- 行折り返し
- ステータスバー
- 補助説明・ヒント
- フォント設定
- 全画面表示
- PHITS、ANGEL、DCHAIN、PHIG-3Dの起動
- MVPのUI表示は日本語とする。画面文言をコードへ直書きせず、将来の英語化が可能なリソース構造にする

印刷、ページ設定、ツールバーの完全再現はMVP優先度を下げる。

## 7. PHITS言語支援

### 7.1 データソース

正本は次の既存資産とする。

```text
%PHITSPATH%\workbench\language_support\data\phits-language-source.json
```

ランタイムでは生成済みの次を使用する。

```text
%PHITSPATH%\workbench\language_support\data\phits-spec.json
```

生成済み`phits-spec.json`を手作業で編集しない。

### 7.2 MVP機能

- PHITSセクション・キーワード等の構文色分け
- セクション名補完
- セクションに応じたパラメータ補完
- キーワードの日本語・英語ホバー説明
- 許容値・既定値・単位の表示（データが存在する場合）

### 7.3 MVP後

- 構文・意味診断
- Cell/Surface/Material番号の定義移動
- 参照検索
- ドキュメントアウトライン
- 値レベル補完
- 必要に応じて既存LSPサーバーを利用

## 8. ファイル処理

### 8.1 文字コード

- UTF-8およびWindows-31J/Shift_JISを扱う。
- 読み込んだファイルの文字コードを可能な限り維持する。
- BOMおよび改行コードを維持する。
- 保存時に暗黙の文字コード変換を行わない。
- ステータスバーへ現在の文字コードと改行形式を表示する。
- 新規ファイルの既定文字コードはUTF-8（BOMなし）、改行はOS既定とする。
- PHITS 3.37で日本語コメントを含むUTF-8入力の編集・実行互換性を受入試験し、不適合の場合はリリース前に既定値を再検討する。

### 8.2 未保存ファイルの実行

実行前に未保存変更がある場合は、次を提示する。

- 保存して実行
- キャンセル

MVPでは未保存内容を一時ファイルとして実行しない。

### 8.3 保存とバックアップ

- 通常の保存は、一時ファイルへの書き込みと同期に成功してから置換する原子的保存とする。
- 上書き保存の直前内容を`.phits-editor/backups/`へ退避し、ファイルごとに1世代だけ保持する。
- 編集中の内容を元ファイルへ自動保存しない。
- バックアップからの復元はユーザー操作で行い、Editorが自動的に元ファイルを上書きしない。

### 8.4 巨大ファイル

- 巨大なPHITS出力をMonacoへ無制限に読み込まない。
- 出力パネルでは末尾または制限された行数だけを保持する。
- 完全な出力は外部ファイルとして開けるようにする。
- 入力行数2,000行を超える場合は、編集支援処理を調整できる設計にする。現行PhitsPadの設定値を初期参考値とする。

## 9. プログラム実行

### 9.1 共通原則

- 内部実行ファイルを直接呼ばず、PHITS配布物の公式ラッパーまたは公式起動経路を利用する。
- 入力ファイルの親ディレクトリを作業ディレクトリとする。
- ラッパーへはフルパスではなく入力ファイル名を渡す。
- 同じ作業ディレクトリで複数のPHITSジョブを同時実行しない。
- Rust側で入力パスを検証し、フロントエンドから任意コマンドを渡さない。
- 通常実行・本番実行のいずれも、PHITS起動直前に主入力のスナップショットと最小実行メタデータを`.phits-editor/runs/<run-id>/`へ保存する。この処理は起動前に完了し、計算中の監視処理を伴わない。
- 実行前に既存の`phits.out`、`batch.out`および既知のタリー出力を検出し、上書きされる可能性を確認画面に表示する。
- 既存出力を自動削除、移動、改名しない。ユーザーは続行またはキャンセルを選ぶ。

PHITSインストール先の選択優先順位:

1. ユーザーが明示的に設定したワークスペース固有のPHITSパス
2. アプリ全体で手動設定したPHITSパス
3. 環境変数`PHITSPATH`
4. OSごとの標準位置（Windowsでは`C:\phits`）
5. 未検出として設定画面へ案内

設定画面は「表示・フォント」と「PHITS実行環境」に分ける。PHITS実行環境では自動検出を既定とし、アプリ全体で使用するインストール先を明示指定できる。明示指定は公式実行入口とラッパーの存在をRust側で検証してからOSのアプリ設定ディレクトリへ保存する。選択したインストール先、検出元、検出バージョン、互換区分およびラッパー検出結果を表示する。システムの`PATH`と`PHITSPATH`は変更せず、実行する子プロセスに解決済み`PHITSPATH`を設定する。ワークスペース固有設定は複数のPHITSインストールを明示的に使い分ける場合だけ作成する。

### 9.2 PHITSラッパー

Windows:

```text
%PHITSPATH%\workbench\task\win\run_phits_no_pause.ps1
```

Linux:

```text
$PHITSPATH/workbench/task/linux/run_phits_no_pause.sh
```

### 9.3 関連プログラム

- ANGEL
- DCHAIN
- PHIG-3D

各OSの`workbench/task/<platform>/`にある実行手順・ラッパーを利用する。関連プログラムごとにRustの限定アダプターを用意する。

## 10. PHITS実行モード

### 10.1 確定仕様

MVPではPHITS実行はユーザー操作からのみ開始する。「通常実行」と「本番実行（計算優先）」の2モードを提供する。

CodexによるPHITS実行要求はMVP後に追加し、ユーザー承認後に同じRust Runnerを使用する。

### 10.2 モード比較

| モード | PHITSプロセス | Codex | UI | エディター終了 |
|---|---|---|---|---|
| 通常実行 | エディターが管理 | 利用可能 | 編集・会話・リアルタイム出力 | 実行中は確認が必要 |
| 本番実行（計算優先） | エディターから完全に切り離す | PHITS起動前にApp Serverを終了 | 終了準備後、PHITSをspawnして直ちに終了 | 計算継続 |

### 10.3 通常実行

- 短時間の試験、入力デバッグ、実行結果の即時確認に使用する。
- stdout/stderrを出力パネルへ表示する。
- 実行中の通常実行を本番実行へ切り替える機能はMVPでは提供しない。本番実行はPHITS起動前に選択する。
- 実行中にエディターを閉じる場合は次を提示する。
  - 停止
  - 閉じるのを中止

### 10.4 本番実行（計算優先）

長時間または計算資源を優先したいPHITS計算に使用する。本番実行の開始フローは次のとおりとする。

1. 未保存ファイルがあれば保存確認を表示する。
2. 実行対象と作業ディレクトリを確認し、起動に必要な引数をすべて確定する。
3. 入力ファイルの相対パス、開始要求時刻、実行モード、入力ハッシュ、検出したPHITSバージョン等の最小メタデータを`.phits-editor/runs/`へ保存する。
4. Codex App Serverを終了する。
5. Monacoの言語支援、ファイル監視、タイマー等、Editor内の非必須バックグラウンド処理を停止する。
6. PHITSをEditorから完全に切り離した独立プロセスとしてspawnする。
7. OS APIがプロセス生成に成功したことだけを確認し、Editorを直ちに終了する。
8. 以後はPHITSだけで計算を継続する。

追加仕様:

- 「起動成功」はOSレベルのプロセス生成成功だけを意味する。PHITS内部の初期化、入力解析、geometry errorの有無までは待たない。
- PHITSとCodex App Serverが同時に稼働する期間を設けない。
- PHITSとEditorが共存するのは、spawn成功からEditor終了までの最短期間だけとする。その間にポーリング、ログ解析、追加メタデータ書き込みを行わない。
- 本番計算中は、Supervisor、常駐Launcher、監視画面、ポーリング処理などEditor由来のプロセスを一切残さない。
- 本番実行ではEditor独自のstdout/stderr監視・収集を行わず、PHITSおよび公式ラッパーが生成する既存ファイルを正本とする。OS上のハンドル切り離しに出力先指定が必要な場合も、常駐プロセスを介さず起動時に直接設定する。
- spawnに失敗した場合はEditorを終了せずエラーを表示する。Codex App Serverは必要になった時点で再起動できるようにする。
- 常駐監視画面は設けない。進捗はPHITS出力ファイルを直接確認するか、Editorを再起動して確認する。
- Editor再起動時に限り、`phits.out`、`batch.out`、タリー出力等のPHITS生成ファイルを一度読み、実行中候補、完了、異常・中断候補、不明の状態を判定する。
- 状態判定に利用するファイル名、終了文字列、更新条件は、対象PHITS版の実出力を調査してPhase 4で確定する。断定できない場合は`不明`と表示し、推測で完了扱いしない。
- 再起動して状態を確認した後も、PHITSプロセスへ従属関係を設定しない。
- 計算終了時にエディターやCodex App Serverを自動起動しない。
- OSのプロセス優先度やCPU affinityはMVPでは変更しない。まずエディターとCodexを終了することで計算資源を解放する。

### 10.5 停止

- 通常停止では、可能な場合に`batch.out`の先頭値を`0`へ変更し、現在バッチ終了後の停止を要求する。
- 本番実行中はEditor由来の停止待受プロセスを置かない。停止する場合はEditorを再起動して対象実行を選ぶか、ユーザーがPHITS標準手順で`batch.out`を操作する。
- `batch.out`停止が利用できない場合、または即時停止が明示された場合の強制停止は段階的に実装する。
- Windowsではプロセスツリー、Linuxではプロセスグループを安全に扱う必要がある。

## 11. Codex連携

### 11.1 接続

- Rustから`codex app-server`を子プロセスとして起動する。
- 既定の`stdio`トランスポートを使用する。
- JSONLとしてJSON-RPCメッセージを送受信する。
- WebSocket接続はMVPでは使用しない。
- Codex CLIが未導入、未認証、オフライン、または起動不能の場合でも、エディター機能とユーザー操作によるPHITS実行は利用可能とする。
- Codexの認証はユーザー環境にある既存のCodex CLIへ委ね、EditorはAPIキー、アクセストークン、セッション情報を保存しない。
- Codex App ServerはCodexパネルを初めて利用する時点で遅延起動する。

### 11.2 ライフサイクル

1. App Server起動
2. `initialize`
3. `initialized`
4. `thread/start`または`thread/resume`
5. `turn/start`
6. イベントを右側パネルへストリーム表示
7. 必要に応じて`turn/interrupt`
8. 本番実行開始時またはアプリ終了時にApp Serverを終了

App Serverの`agentMessage`本文とストリーミング差分は、Codexに合わせたMarkdown表現として表示する。見出し、段落、強調、取消線、インラインコード、コードブロック、引用、番号付き／番号なし／タスクリスト、表、Markdownリンクを扱い、生のHTMLは実行しない。リンクは青系の意味色で示し、ユーザーがクリックしたHTTP/HTTPS URLだけをOS既定ブラウザーへ渡す。その他のスキームと不正なURLは非クリック表示とする。

### 11.3 会話保存

- 会話本文・ターン・ツール実行履歴はCodex App Server側を正本とする。
- エディターは`thread.id`とワークスペースの主入力との関連だけを`.phits-editor/codex/threads.json`へ保存する。
- `thread/read`、`thread/list`、`thread/resume`を通じて履歴を参照・再開する。
- Codexの内部JSONLまたは内部SQLiteを直接操作しない。

### 11.4 権限

MVPの確定初期値:

- Codexの`cwd`: 開いているPHITSワークスペース
- サンドボックス: `workspaceWrite`
- 読み取り: 開いているワークスペース内を許可。ワークスペース外は許可しない
- 書き込み可能範囲: 開いているワークスペース内だけ
- ファイル変更: App Serverが要求した操作許可と、書き込み完了後の内容レビューを分離する。許可が必要な場合は変更前に確認し、完了後は常に差分を表示する
- コマンド実行: コマンド、引数、作業ディレクトリを表示し、実行ごとに承認を求める
- ネットワーク: 既定で無効。必要時のみ目的を表示してユーザー承認を求める
- 読み取り専用の相談モードを用意する

承認UIでは少なくとも、対象スレッド、対象ターン、操作内容、作業ディレクトリ、許可範囲を表示する。

### 11.5 コンテキスト送信

自動的に全ファイル・全出力を送らない。ユーザー要求に応じて次を文脈として利用する。

- アクティブな入力ファイル
- 選択範囲
- カーソル位置
- 実際にEditor診断が存在し、ユーザーが明示的に添付した診断メッセージ（空の診断は表示・送信しない）
- 明示的に選択されたPHITS出力
- `.phits-editor/codex/context.md`

大きな出力は必要部分だけを渡し、完全なファイルはローカルパスとしてCodexが必要時に読む。

### 11.6 CodexによるPHITS実行（MVP後）

1. CodexがPHITS実行を要求する。
2. エディターが入力ファイル、作業ディレクトリ、実行モードを示す承認画面を表示する。
3. ユーザー承認後、Codexではなくアプリ所有のRust Runnerが公式ラッパーを起動する。
4. 実行結果をCodexのツール結果として同じスレッドへ返す。

実験的APIへの依存はアダプター内へ隔離し、MVPでは採用しない。

## 12. リソース管理

### 12.1 基本方針

- 待機中のエディターCPU使用を最小化する。
- 大量出力の再描画・再解析を行わない。
- Codexを使わない間はApp Serverを遅延起動できるようにする。
- 本番実行ではPHITSを起動する前にApp ServerとEditor内の非必須処理を停止し、spawn成功直後にエディター本体を終了する。
- 本番PHITS計算はエディターの生存に依存しない。
- 本番実行の計算終了後も、エディターやApp Serverを自動起動しない。
- 本番計算中にEditor由来の常駐プロセスやポーリング処理を残さない。

### 12.2 性能受入目標（暫定）

代表的PHITS入力を使い、次を比較する。

1. 公式ラッパー単独
2. エディターを開きCodex未接続
3. エディターを開きCodex App Server待機
4. 本番実行後にエディター終了

測定項目:

- PHITS経過時間
- PHITS CPU時間
- システムメモリ
- ページング
- ディスクI/O
- OpenMP/MPIスケーリング

暫定目標は、Codex未接続・エディター待機時のPHITS性能差を実行変動込みで2%以内とする。物理メモリ不足時はエディター終了を推奨する。

## 13. セキュリティ・プライバシー

- フロントエンドへ任意コマンド実行APIを公開しない。
- Rust Runnerは既知のPHITS関連プログラムと公式ラッパーだけを起動する。
- パスをコマンド文字列へ連結せず、実行ファイルと引数を分離する。
- Codexへ送るファイル・選択範囲をUIで確認可能にする。
- 会話履歴やスレッドIDをGitへ誤登録しないよう`.gitignore`を生成する。
- `.phits-editor`全体をGit対象外にする設定も提供する。
- 認証情報をプロジェクトディレクトリへ保存しない。
- 利用状況テレメトリー、解析イベント、クラッシュ情報を自動送信しない。
- 診断情報はユーザーが明示的に生成・保存した場合だけ出力し、外部へ自動送信しない。

5. PHITS起動前に本番実行を選択し、Editor終了後も計算が継続することを確認する。
6. Editorを再度開き、実行状態と会話を復元する。
7. Codexを利用不能にしても編集とPHITS実行ができることを確認する。
8. 公式ラッパー単独実行と本番実行の性能差を測定する。

## 17. 開発体制

### 17.1 Codexによる開発

ChatGPTデスクトップ版のCodexを主開発エージェントとして使用する。設計判断、コード変更、テスト結果をリポジトリ内文書とコミット単位で残す。

### 17.2 マルチエージェント

初期の共通インターフェース設計は単一エージェントで行う。境界が確定した後、独立性の高い作業に限定して並列化する。

候補:

- UI・Monaco・言語支援
- Windows Runner
- Linux Runner・実機受入（Ubuntu移植時。CIのソース検査は先行して維持）
- Codex App Serverクライアントとプロトコルテスト
- セキュリティ・テストレビュー

同じファイルを複数エージェントが同時編集しない。主エージェントが統合と最終検証を担当する。

## 19. リスクと対策

| リスク | 対策 |
|---|---|
| App Server仕様変更 | `CodexAppServerClient`へ隔離し、Codexバージョンを検出して生成スキーマと互換試験を行う |
| PHITS実行がエディター終了に巻き込まれる | 本番実行をOS固有の切り離し起動として統合試験する |
| Codex停止後にPHITSのspawnが失敗する | Editorを終了せずエラーを表示し、Codexは必要時に再起動できるようにする |
| PHITS生成ファイルだけでは終了状態を断定できない | 状態を`不明`として扱い、対象PHITS版ごとの判定規則を実出力で検証する |
| 3.37より新しいPHITSでラッパーや出力形式が変更される | 未検証警告を表示し、バージョン依存処理をアダプターへ隔離する。利用を禁止せず、問題報告に診断情報を添付できるようにする |
| メモリ不足でPHITSが低速化 | 本番実行時にApp Serverとエディターを終了し、性能受入試験を行う |
| 巨大出力でUIが停止 | 出力保持量を制限し、全文はファイルとして扱う |
| 文字コード破損 | 元エンコーディング・BOM・改行を保持し、往復テストを行う |
| 同一フォルダで出力が衝突 | フォルダ単位の実行ロックを設ける |
| 既存ディレクトリに複数の入力候補がある | 直接開いたファイルまたは現在選択中の入力だけを実行対象としてRust Runnerまで明示的に渡し、未選択時は起動を拒否する |
| スレッドIDが別端末で無効 | App Serverで存在確認し、新規作成・再関連付けを可能にする |
| 任意コマンド実行の露出 | Rust側の限定RunnerとCodex承認UIを使用する |

## 20. 配布前に再確認する事項

実装判断は完了している。次の項目だけを限定配布または一般配布の直前に再確認する。

1. 正式名称（開発中はPHITS AI Editor）と正式bundle identifier
2. Ubuntu版の開発を開始する時点での対象Ubuntu LTSと必要なCodex実行環境
3. PHITSおよび関連資産を同梱しない構成を含む配布・ライセンス表示
4. 個人利用alpha版以降のWindowsコード署名方針（Ubuntuは移植開始時に別途決定）

MVPでは印刷・ページ設定を含めず、個人利用Windows alpha版を先行する。Codex CLI 0.153.1を最低互換基準とし、それより古い版ではCodex機能だけを無効化する。0.153.1以降はインストール済みCLI自身が生成するApp Server Schemaを起動時に検査し、会話・スレッド・ファイル編集・承認を機能単位で有効化する。実行履歴と入力スナップショットは自動削除しない。PHITS状態判定は開始前の出力指紋と新しい`phits.out`の正常終了文字列、`*_geo.out`の生成・更新を用い、断定できない場合は状態不明とする。

## 22. 確定事項の要約

- UIは「現行PhitsPad相当 + 右側Codexパネル」とする。
- Tauri 2 + Rust + React/TypeScript + Monacoを採用する。
- `0.0.1-alpha`はWindows 11 x64のみを公式バイナリ対象とする。Ubuntu LTS x86_64は将来の移植対象とし、実機またはVM受入が完了するまで公式バイナリを公開しない。
- PHITS 3.37を検証済み・正式対応版とし、それより新しい版とバージョン検出不能時は警告付きで実行を許可する。3.37より古い版では入力編集だけを許可し、PHITS実行を無効化する。
- 任意の`.inp`親ディレクトリをワークスペースとし、ワークスペース直下の複数`.inp`/`.pht`から現在の実行対象を1件選択する。
- `.inp`/`.pht`以外の補助テキストは複数編集可能とするが、実行対象にはしない。
- プロジェクト固有メタデータを`.phits-editor`へ保存する。
- 会話本文はCodex側を正本とし、プロジェクトには関連情報のみ保存する。
- 既存ファイルの文字コード・BOM・改行を維持し、新規ファイルはUTF-8（BOMなし）を既定とする。
- 原子的保存と、`.phits-editor/backups/`内の直前版バックアップ1世代を採用し、元ファイルへ自動保存しない。
- PHITS実行は公式ラッパーを使用し、同じフォルダで同時実行しない。
- PHITSパスは明示的なワークスペース設定、アプリ全体設定、`PHITSPATH`、標準位置の順で選択する。通常は自動検出を使用する。
- 実行直前に主入力スナップショットと最小メタデータを保存し、既存出力の上書き可能性を警告する。既存出力は自動整理しない。
- MVPではPHITS実行はユーザー操作からのみ開始する。
- 「通常実行」と「本番実行（計算優先）」の2モードを実装する。
- 実行中の通常実行から本番実行への途中切替は行わず、本番実行は起動前に選択する。
- 本番実行では、PHITS起動前にApp ServerとEditor内の非必須処理を停止し、OSレベルのspawn成功だけを確認した直後にEditorを終了する。
- 本番計算中はSupervisor、常駐Launcher、監視・ポーリング処理を残さず、次回起動時にPHITS生成ファイルから状態を判定する。
- Codex未導入・未認証・オフラインでも、編集とユーザー操作によるPHITS実行を利用可能とする。
- Codexはワークスペース内だけを読み書き対象とし、ファイル変更は差分承認、コマンドは実行ごとの承認とする。
- MVPのUIは日本語とし、将来の英語化が可能なリソース構造にする。
- `0.0.1-alpha`の配布形式はWindows向けNSISとポータブルZIPとする。将来のUbuntu移植では`.deb`を候補とし、いずれもPHITS本体とCodex認証情報を同梱しない。
- テレメトリーや診断情報を自動送信しない。
- Codexによる承認付きPHITS実行はMVP後に追加する。

## 23. Codex Editor統合（実装仕様）

- Codexパネルの既定幅はウィンドウ内側の1/3、最小360px、最大1/2とし、本文14px・`#2F2F2F`・行間1.6・メッセージ間隔20pxを基準とする。Codex回答は透明背景、ユーザー発言だけを薄いグレーの吹き出しで表示する。
- 会話表示は新規メッセージとストリーミング追記を最新位置まで自動追従する。ユーザーが下端から48pxを超えて上へスクロールした場合は過去ログ閲覧を優先して追従を一時停止し、次の送信またはスレッド切替で追従を再開する。
- スレッドIDの手入力は提供しない。App Serverのタイトルを正本とし、タイトル未生成時は最初のユーザー発言から36文字以内の暫定タイトルを作る。一覧には最終利用日時を併記し、右クリックまたはShift+F10から名前変更と確認付き恒久削除を行う。
- 各ターンは通常メッセージと`PHITS_EDITOR_CONTEXT_V1`を別の`input`項目として送る。Contextには相対ファイルパス、実行対象、カーソル、選択、未保存状態、開いたタブ、PHITS版を含める。診断フィールドは将来互換用に維持するが、実診断がない限りComposerへチップを出さず自動添付もしない。選択本文は64 KiB、Context全体は128 KiBを上限とし、超過本文は送らず警告する。履歴にはContext本文を表示しない。
- 変更可能なターンで編集を依頼された場合、CodexにはApp Server組み込みファイル編集を実行させ、`fileChange`イベントを承認UIの唯一の変更提案経路とする。チャット本文へ表示されたunified diffや置換テキストは変更案として自動解釈・適用せず、組み込み編集が完了していない限り編集完了として扱わない。
- App Serverが`fileChange`対象を絶対パスで通知した場合は、実体または親ディレクトリを正規化し、現在のワークスペース配下に収まると確認できたものだけ相対パスへ変換して承認UIへ渡す。ワークスペース外、親参照、シンボリックリンク／ジャンクション越しの対象は自動拒否する。
- 未保存文書を変更可能モードで送る場合は、保存して送信、保存せずそのターンだけ相談モードで送信、送信中止を選べる。相談モードの変更・権限要求はRust側で自動拒否する。
- 承認方式はアプリ全体設定として、確認優先（`untrusted` + `workspaceWrite`）、相談のみ（`untrusted` + `readOnly`）、必要時のみ確認（`on-request` + `workspaceWrite`）を提供する。`never`と`dangerFullAccess`は提供しない。ネットワークとワークスペース外書き込みは禁止する。
- 承認UIはApp Serverの`availableDecisions`に従い、今回のみ許可、接続中許可、拒否して継続、中止してターン中断、提示された実行規則の許可に対応する。接続中許可はApp Server切断で解除する。
- `fileChange`の操作許可が必要な場合は、App Serverのunified diffを変更前のディスク全文へ厳密に適用して提案後全文を復元し、中央Monacoを読み取り専用の差分画面へ切り替える。この段階の操作は「拒否／中止／今回のみ許可／接続中許可」とし、App Serverの`availableDecisions`に存在するものだけを示す。「採用／却下」とは呼ばない。
- Codexの書き込み完了後は承認方式にかかわらず差分を表示し、「Codexの変更・未確認」とする。既定はインライン表示とし、十分な横幅がある場合は左右比較へ切替可能にする。追加を緑、削除を赤、行番号・ガター・概要ルーラーを表示し、前後の変更箇所と複数変更ファイルを移動できる。ユーザーは「変更を保持」で確認済みにするか、「元に戻す」でターン単位チェックポイントへ復元する。行単位・hunk単位の部分採用はMVP後とする。
- `item/started`時点の実ファイルを原バイトのまま履歴化し、同じ`turnId`の複数パッチ・複数ファイルを1変更グループとして扱う。グループ復元は全対象の現在ハッシュと復元可能性を先に検証し、一部だけを復元しない。文字コード、BOM、改行形式を保持し、履歴は`.phits-editor/codex/changes`へ保存する。未確認状態は再起動後も復元し、Explorerとタブへ控えめなAIマーカーを表示する。
- 通常Editorの`Ctrl+Z`はMonacoのUndo履歴を使って現在ファイルだけを未保存状態へ戻し、`Ctrl+Shift+Z`でやり直す。複数ファイルをまとめて戻す場合は差分画面のターン単位「元に戻す」を使う。
- ターン開始時にディスクとMonacoバッファのSHA-256、更新日時、未保存状態を記録する。承認前に変化があれば自動承認せず競合とし、Codex変更完了後はディスクを再読込する。未保存バッファとの競合時は保存を止め、差分比較からEditor側またはCodex側を選択する。
- Editorの右クリックには、選択範囲の説明・修正、現在のファイルのレビュー、コメント追加、Codexコンテキストへの追加を置く。診断相談は実診断プロバイダー完成後に、診断が存在する場合だけ提供する。`.out`はExplorerの右クリックから明示的に解析対象へ追加する。
- Codex CLI 0.153.1から生成したJSON Schemaを`schemas/codex/0.153.1`へ固定し、互換試験の基準とする。
- 起動時互換性プローブはインストール済みCodex CLIから一時Schemaを生成し、会話・スレッド・ファイル編集・承認の契約を個別判定する。会話契約がない場合は接続を禁止し、編集または承認契約がない場合は相談のみへ縮退する。未知の承認値や変更形式は許可しない。
- GitHub Actionsは毎週および手動実行時に最新版Codex CLIを導入し、同じ機能契約を検査する。CLIの更新だけではEditorを再配布せず、互換試験の失敗または安全性修正が必要な場合に更新する。
